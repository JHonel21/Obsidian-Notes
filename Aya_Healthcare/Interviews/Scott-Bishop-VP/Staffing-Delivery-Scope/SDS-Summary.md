Phase 1: Targeted Discovery (0–48 hours)

Objective: Define the real problem and boundaries

Outputs:

- Business objectives (reduce clinician burnout, optimize Epic workflows, etc.)
- In-scope vs out-of-scope
- Constraints (timeline, budget sensitivity, internal capabilities)
- Known unknowns (data access, integrations, governance)

Phase 2: Scope Decomposition

Objective: Translate problem → work packages

You break the initiative into capability domains:

Example (EHR Optimization):

- Clinical workflow analysis
- Build/config optimization
- Reporting & analytics
- Integration adjustments
- Training & change management

Each becomes a track of work, not a vague deliverable.

2. Staffing Plan (Core of Pre-Sales Value)

Step 1: Role Mapping

For each workstream, define:

- Role type (Epic analyst, data engineer, PM, etc.)
- Level (junior, senior, SME)
- Quantity
- Duration

Example (simplified)

|   |   |   |   |   |
|---|---|---|---|---|
|Workstream|Role|Level|Qty|Duration|
|Workflow optimization|Epic Analyst|Senior|2|12 weeks|
|Integration|Interface Engineer|Mid|1|8 weeks|
|Oversight|Program Manager|Senior|1|16 weeks|

Step 2: Effort Modeling

Translate into:

- Hours or FTEs
- Phased allocation (not flat staffing)

Example:

- Phase 1 (Assessment): heavy SMEs
- Phase 2 (Build): more mid-level resources
- Phase 3 (Stabilization): tapering model

Step 3: Cost Alignment (High-Level)

You don’t need exact pricing, but:

- Blend rates by role
- Ensure margin viability
- Avoid under-scoping

3. Delivery Framework (How Work Gets Done)

This is where many candidates are weak.

You are defining how Aya delivers, not just who.

Standard structure

Phase-Based Model

- Phase 1: Assessment

- Current state analysis
- Gap identification
- Roadmap

- Phase 2: Design

- Future state workflows
- Architecture definition
- Validation with stakeholders

- Phase 3: Implementation

- Build/config
- Integration work
- Iterative validation

- Phase 4: Optimization

- Performance tuning
- Adoption support
- Metrics tracking

Delivery Characteristics You Must Define

- Onsite vs remote mix
- Client vs Aya responsibility split
- Governance model (cadence, reporting)
- Dependency management

4. Scope Definition (Where Deals Are Won or Lost)

This is about precision and protection.

You explicitly define:

In Scope

- Exact deliverables
- Systems involved
- Level of support

Out of Scope

- Anything that can create ambiguity later

Assumptions

- Data availability
- Client participation
- Tooling access

Risks

- Integration complexity
- Change resistance
- Timeline compression

Example (tight language)

“Solution assumes Epic access is provisioned within 2 weeks and client SMEs are available for weekly validation sessions.”

- Right-level resourcing
